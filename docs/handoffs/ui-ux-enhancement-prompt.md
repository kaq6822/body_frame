```text

다른 워크트리라면 브랜드 변경과 이 문서를 포함한 기준 커밋/패치가 있는지 확인하고
누락된 상태로 구현을 시작하지 마세요.

기본 구현 범위는 ROADMAP의 BF-01~04입니다. 검토 문서는 코드 읽기에 따른 근거이며
실기기 재현 결과가 아닙니다. 각 항목은 먼저 Fake를 이용한 결정론적 재현 테스트를

- BF-01: 리뷰·갤러리 저장 요청의 불변 스냅샷, 작업 중 재촬영/입력/목록 변경과
  중복 실행 방어, 실패 후 원본·입력 보존 및 재시도. Completer로 저장을 지연시켜
  타이밍 충돌을 재현하세요. 기존 staging·transaction·rollback을 보존하세요.
- BF-02: 방향 모아보기 경과일, 자동 비교 날짜, 이전 사진 가이드의 라벨 기준 일치.
  normalizeLabel 기준을 재사용하세요. 자동 추천과 기본 가이드는 본인 기록을

  표시하세요. 회원/프로필/대상 테이블을 새로 만들지 마세요.
- BF-03: 비교 기간 계산을 기존 daysBetween 또는 공통 순수 함수로 통일하세요.
  날짜 교환, 같은 날, 월/연 경계, 시각, 서머타임에 대한 테스트를 추가하세요.
- BF-04: 앱·격자 설정 저장의 진행/실패/재시도, 연속 변경 저장 순서 보장.
  빠른 조작에도 마지막 선택이 UI와 저장값에 남도록 구현하고 역순 완료 Fake로
  검증하세요. 격자 실시간 미리보기는 유지하세요.

함께 docs/device-smoke-checklist.md의 같은 날 촬영 항목을 현재 코드와 테스트의
'촬영마다 새 기록 생성' 계약으로 정정하세요. 기존 기능을 기록 합치기로 바꾸지 마세요.

BF-05~08, 새 검색 화면, 영속 촬영 초안, DB 대표 사진 필드, 일괄 삭제, 아이콘/시작
화면과 출시 signing은 이번 기본 범위에 자동 포함하지 마세요. 필요성이 새로 확인되면
ROADMAP.md에 근거를 기록하세요. 남은 구현과 완료 상태의 단일 관리 문서는 ROADMAP입니다.

오프라인 제품 경계, 원본 무변형, 상대 파일 경로, 명시적 삭제 확인, D2D 규칙을
준수하세요. provider 인터페이스를 사용하고 플랫폼 I/O를 Fake로 대체 가능하게 두세요.
주요 UI에는 Semantics.identifier와 ValueKey를 함께 제공하세요. DB 변경이 필요하면
schemaVersion과 누적 마이그레이션을 추가하고 플랫폼 프로젝트를 재생성하지 마세요.

검증은 관련 회귀 테스트, flutter analyze, flutter test입니다. 수정한 Dart 파일만

다시 확인하세요. 카메라·저장 동작을 Android/iOS에서 확인할 장비가 없으면 미검증을
명확히 남기고 실기기 확인까지 끝났다고 보고하지 마세요.

완료한 항목은 테스트와 함께 ROADMAP에서 제거하세요. 최종 답변에 변경 동작,
```
