# 실기기 스모크 테스트

스토어 제출 후보 빌드에서 아래 핵심 흐름만 실기기로 확인합니다. 결과에는 기기, OS,
빌드 번호, 성공 여부와 실패 화면 또는 로그를 함께 남깁니다.

## 테스트 조합

- [ ] Android 10(API 29) 기기
- [ ] Android 13 이상 기기
- [ ] Face ID 또는 Touch ID를 사용할 수 있는 iPhone

## 설치와 권한

- [ ] 새로 설치한 앱 이름이 `Body Frame`으로 표시된다.
- [ ] 촬영 화면에 처음 들어갈 때 카메라 권한만 요청하고 마이크 권한은 요청하지 않는다.
- [ ] 카메라 권한을 거부해도 안내 후 다시 시도하거나 이전 화면으로 나갈 수 있다.
- [ ] Android 13 이상에서 갤러리 등록 시 광범위한 저장소 권한 없이 시스템 선택기가 열린다.
- [ ] iOS에서 사진 선택·저장 권한 문구가 앱 기능과 일치하고, 거부 후에도 앱이 종료되지 않는다.

## 촬영과 사진 기록

- [ ] 선택한 회원과 방향으로 사진이 저장되고 앱을 재실행해도 남아 있다.
- [ ] 같은 회원·방향의 최신 이전 사진만 반투명 가이드로 표시된다.
- [ ] 이전 사진 가이드를 켜고 끌 수 있고 투명도를 조절할 수 있으며 비율이 왜곡되지 않는다.
- [ ] 촬영 결과 원본에는 이전 사진 가이드와 격자선이 합성되지 않는다.
- [ ] 앱을 백그라운드로 보냈다가 복귀하거나 다른 카메라 앱을 사용한 뒤에도 촬영을 재개할 수 있다.
- [ ] 갤러리 등록, 사진 교체, 삭제 후 앱을 재실행해도 결과가 유지된다.
- [ ] Android 개발자 옵션의 `활동 유지 안 함`을 켠 상태에서 갤러리 선택 후
  돌아오면 원래 회원의 등록 목록에만 결과가 복구되며 자동 저장되지 않는다.
- [ ] 같은 조건에서 대표 사진은 원래 편집 회원의 미리보기에만 나타나고, 사진
  교체 결과는 원래 사진 화면에서 `교체 적용`을 누르기 전까지 기존 원본을
  변경하지 않는다.

## 잠금과 로컬 데이터 보호

- [ ] 생체 인증을 켠 뒤 앱을 완전히 종료해 다시 열면 잠금 화면이 먼저 표시된다.
- [ ] 잠금 상태에서 백그라운드로 보냈다가 복귀하면 정책에 맞게 다시 인증한다.
- [ ] iOS 앱 컨테이너의 `Documents`와 `Library/Application Support`가 백업 제외 및 완전 파일 보호 대상으로 설정된다.
- [ ] Android 앱 데이터가 시스템 자동 백업·기기 간 전송 대상에 포함되지 않는다.

## 내보내기와 복원

- [ ] Android 10과 Android 13 이상에서 비교 이미지를 갤러리에 저장할 수 있다.
- [ ] 비교 이미지 공유 시 선택한 레이아웃과 안내 문구가 일치한다.
- [ ] 비밀번호와 확인값을 입력해 `.bfbackup` 파일을 생성·저장·공유할 수 있다.
- [ ] 올바른 비밀번호로 `.bfbackup`을 복원하고, 취소하면 기존 데이터가 유지된다.
- [ ] 틀린 비밀번호나 변조된 `.bfbackup`은 거부되고 기존 데이터가 변경되지 않는다.
- [ ] 이전 버전의 평문 ZIP 백업을 선택해 복원할 수 있다.
- [ ] 앱 삭제·재설치 또는 새 기기에서 `.bfbackup`을 복원한 뒤 사진, 대표 사진과
  스튜디오 로고를 실제로 열 수 있다.

## 오프라인과 개인정보

- [ ] 비행기 모드에서도 촬영, 기록 조회, 비교, 앱 잠금의 핵심 기능이 동작한다.
- [ ] 오류 로그에 회원 이름, 연락처, 메모, 로컬 파일 경로가 노출되지 않는다.
