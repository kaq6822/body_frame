# BodyMark 전체 디자인 시안 및 검수

대상 Stitch 프로젝트: https://stitch.withgoogle.com/projects/2398877984889259331

## 확정된 제품 방향

- 필라테스 강사를 시작으로 요가·피트니스 강사까지 확장 가능한 회원 기록 도구.
- 한 강사의 휴대폰에서 오프라인 사용. 로그인·서버·클라우드·예약·결제·출석을 추가하지 않는다.
- 회원의 시작 배경·목표·통증 및 주의사항·회원 전달 내용·강사 관찰을 기록한다.
- 기본 기록 단위는 실제 날짜와 시작 시각이 있는 레슨이다. 작성·수정 시각, 사진 촬영 시각은 별개다.
- 사진 없이 일지만 저장해도 완성된 기록이다. 수업 전·후 사진은 선택 사항이다.
- 촬영 순서는 정면 → 좌측면 → 우측면 → 후면. 같은 회원·같은 방향의 기준 사진을 사용한다.
- 원본 사진의 비율·방향·전신을 보존한다. 몸이나 자세를 자동 변형하지 않는다.
- 비교·공유는 강사가 선택한 두 기록에서 수행한다. AI 진단·가상 개선 수치·자동 정렬을 약속하지 않는다.
- 앱 잠금·워터마크·앱 내 백업/복원은 이번 범위에 없다. 기존 기기 간 이전 정책을 유지한다.

이 문서는 사용자가 새로 결정한 제품 방향에 따른 **디자인 명세**다. 기존 개인 앱의
구현 완료나 데이터 구조 변경을 뜻하지 않는다. 구현·배포 잔여 작업은 ROADMAP.md에서 관리한다.

## 공통 디자인 및 상호작용

- 밝은 중립 배경, 진한 글자, 딥 틸 단일 강조색. 한국어 중심. 실제 390×844 내외 모바일 화면.
- 주요 글자 16px, 보조 글자 13px 이상을 기본으로 하고, 터치 영역은 48dp 이상.
- 하단 탐색은 회원 / 기록 / 설정. 회원 목록이 기본 진입점이며 장식용 대시보드를 두지 않는다.
- 레슨 입력·회원 편집·기록 열람·촬영은 일반 전체 화면. 긴 입력을 작은 다이얼로그에 넣지 않는다.
- 짧은 날짜·시간 선택과 제한된 옵션에만 선택창을 사용한다. 시트 위에 시트를 연쇄하지 않는다.
- 삭제 및 작성 내용 폐기는 명시적으로 확인한다. 일반 저장 성공은 비차단 안내로 표현한다.
- 카메라 복귀·날짜 선택·키보드 표시 중에도 입력 내용을 유지한다. 사진 부재를 실패로 표시하지 않는다.
- 예시는 가상 인물·정보만 사용한다. 회원 정보는 공유 기본값에서 제외한다.

## 화면 범위와 검수 기준

| 묶음 | 화면 범위 | 확인 기준 |
|---|---|---|
| A | 회원 목록, 회원 등록, 회원 상세, 일지 작성, 사진 포함 작성, 일지 상세 | 탐색·기본 입력·사진 선택성·레슨 시각 구분 |
| B | 바로 촬영 준비, 기준 기록 선택, 카메라, 촬영 검토, 사진 상세, 촬영 가이드 | 회원/레슨 연결·4방향·원본 비율·건너뛰기·재촬영 |
| C | 전체 기록, 비교 대상 선택, 나란히 비교, 겹쳐 비교, 공유 구성, 공유 미리보기 | 같은 회원/방향·날짜 구분·비율 보존·공유 정보 선택 |
| D | 설정, 최초 회원 없음, 회원 기록 없음, 검색 결과 없음, 카메라 권한 거부, 저장 실패 | 다음 행동·재시도·일지 계속 작성·입력 보존 |
| E | 데이터 안내, 삭제 확인, 미저장 이탈, 일부 방향만 촬영, 갤러리 사진 연결, 기존 기록 연결 | 경계·손실 방지·명확한 선택·추정 연결 금지 |
| F | 키보드 입력, 레슨 일시 선택, 비교 방향 없음, 공유 실패 | 입력 가림·짧은 선택·불가능한 비교·생성 실패 복구 |
| G | 개인정보 안내, 회원 삭제 확인, 첫 촬영, 비교 사진 부족, 이전 사진 표시 설정, 사진 있는 레슨 상세 | 보관·삭제 범위·기준 사진 부재·선택 패널·저장된 사진 레슨 |
| N | 사진만 기록, 사진 한 장 삭제 확인, 사진 불러오기 실패, 기록 불러오기 실패 | 선택적 메모·삭제 범위·실패/빈 상태 구분·재시도 |

검수는 생성 요청이 아니라 **저장된 화면 리소스·이미지·HTML**을 근거로 한다.
정적 시안으로 확인할 수 없는 실제 터치·키보드·스크린리더·저장 동작은 구현 검증과 구분한다.

## 모달 검토 근거

- Apple Modality: 명확한 이점이 있을 때 사용, 짧고 단순한 작업, 겹친 모달 최소화.
  https://developer.apple.com/design/human-interface-guidelines/modality
- Apple Sheets: 길거나 복잡한 흐름에는 다른 표현 고려, 한 번에 하나의 시트.
  https://developer.apple.com/design/human-interface-guidelines/sheets
- Apple Alerts: 꼭 필요한 행동에만 알림, 단순 정보 및 일상적 성공 알림 최소화.
  https://developer.apple.com/design/human-interface-guidelines/alerts

이 지침은 사용자 거부감의 빈도나 강도를 측정한 실험 결과가 아니다. 강사의 실제 불편함은
일지 단독 저장·과거 레슨 작성·촬영 복귀·사진 비교 과제로 사용성 검증해야 한다.

## 생성 및 검수 이력

- 시작 상태: 기존 핵심 시안 15개와 이미지 자산 4개 확인. 구버전·개선안 혼재.
- 기존 레슨 v1 및 UX v3 일부 화면은 2560×2048 캔버스 안의 작은 모바일 UI로 출력됨.
- `edit_screens`의 완료 응답만으로 저장 반영을 입증할 수 없었던 이력이 있어,
  신규 화면 리소스 생성 후 다시 다운로드하여 확인한다.
- 전체 세트 생성과 검수 결과는 아래에 실제 리소스 ID와 함께 누적한다.

### 1차 A 검수 (회원·일지)

- 생성 설정 수정 후 6개 모두 MOBILE, 폭 780 확인. 사진 포함 작성은 스크롤 콘텐츠 높이 2006.
- 사진 없는 레슨을 빨간 오류나 미완료로 표시하지 않는 점, 실제 레슨/촬영 시각 분리는 확인.
- 수정 대상: 회원 목록의 오프라인·안전 보관/자물쇠 장식, 일지 작성의 반복 저장 설명,
  일지 상세의 임의 `50분 수업` 및 저장 모드 표기, 사진 작성의 고정 3:4 설명.
- 회원 상세 썸네일이 서로 다른 배경·인물 크기를 섞어 보여 일관된 가상 자료로 교체 필요.
- 회원 등록의 주의사항은 스크롤 아래로 이어짐. 저장 헤더 유지 여부는 HTML과 모바일 렌더 검증 필요.

### 생성·캔버스 저장 검증

- 기본 생성 경로가 요청과 달리 DESKTOP을 반환해, 명시적 모델/모바일 생성 조건으로 변경.
- 신규 결과의 deviceType=MOBILE과 780px 세로 이미지를 확인했다.
- get_screen으로 신규 리소스가 존재해도 list_screens에 없으면 캔버스 연결 누락이다.
- 프로젝트를 새로 읽어 기존 screenInstances를 보존하고 신규 sourceScreen 참조만 추가한 뒤,
  list_screens 재조회로 포함 여부를 확인하는 방식으로 교정했다.
- 원본/중간 시안은 삭제하지 않는다. 최신 검수본은 최종 화면표에서 별도로 지정한다.

### 1차 B 검수 (촬영)

- 6개 모두 MOBILE이며 촬영 준비/기준 선택/카메라/검토/뷰어/가이드 역할이 구분됨.
- 카메라 전신과 기본 셔터는 확인. 다만 `건너뛰기`/`가이드`가 단어 중간에서 줄바꿈되어 수정 필요.
- 촬영 검토에 별도 메모 입력이 다시 생성되어 일지 작성과 중복됨. 삭제 대상.
- 촬영 준비의 `자세를 맞춥니다` 문구는 기존 자세를 따라 하라는 뜻으로 읽힐 수 있어
  `이전 사진의 위치와 크기를 참고해요`로 교체 대상. 고정 3:4/필수선택 장식도 제거 대상.
- 기준 기록 선택은 긴 스크롤 출력(780×2206). 하단 선택 버튼 고정과 목록 밀도 조정 대상.

### 1차 C 검수 (비교·공유)

- 비교 대상 선택·나란히·겹쳐 보기·구성·미리보기 흐름과 이름/메모 기본 OFF 확인.
- 수정 대상: 기록 목록의 불필요한 사진 미포함 표기, 비교 선택의 과도한 4방향 썸네일,
  구성 화면과 미리보기의 서로 다른 이미지, 미리보기의 BodyMark/슬로건(워터마크성 표현),
  날짜·시간 ON인데 결과물에 시간이 빠진 점.
- 공통 사진 URL을 고정하고 미리보기/비교의 이미지·비율·날짜·시간을 일치시키는 수정본 요청.

### 현재 작업 상태

- A/B/C 18개 MOBILE 화면 리소스를 생성·다운로드·육안 검수했으며, 캔버스 연결 후
  list_screens에 모두 포함됨을 확인했다. 아직 수정 대상이 있어 최종 통과를 뜻하지 않는다.
- D(설정·빈 상태·권한·저장 실패) 요청은 응답 대기 중이다. 동일 실행 세션을 재확인하며
  중복 생성하지 않는다. E/F/G의 나머지 상태, H/I/J의 확인된 결함 수정 프롬프트는 준비됨.
- 검수용 이미지·HTML·원문 결과·갤러리는 `.design-review/bodymark/`에 보관하며 Git에서 제외한다.
- 브라우저 확인은 캔버스 연결 누락 진단에만 시도했고, 생성 요청을 제출하지 않았다.
  이후 작업은 사용자의 지적에 따라 브라우저 없이 MCP/API로만 수행한다.

### D 응답 회수 및 규격 수정

- 클라이언트가 대기 중이더라도 Stitch 프로젝트 세션 목록에서 생성 세션
  `15430851006233986703` 의 DONE 상태와 6개 화면 결과가 존재함을 확인했다.
- 동일한 완료 결과를 회수했으며, 통신 타임아웃을 이유로 같은 생성을 중복 실행하지 않았다.
- 회수한 D의 6개 화면은 DESKTOP으로 모바일 통과 조건을 충족하지 않았다.
  모바일 수정본을 새 요청으로 생성하며, 이전 D는 최종 채택 대상에서 제외한다.
- 이후 MCP 응답과 서버의 실제 세션 상태를 대조해 DONE 결과를 직접 회수하도록 개선했다.

### D 모바일 검수

- 모바일 변형 생성으로 설정·첫 시작·회원 기록 없음·검색 결과 없음·카메라 권한 안내·저장 실패
  6개 모두 MOBILE로 확보했다. 신규 생성과 변형 API의 결과 수가 달라 입력 화면 수에 맞춰
  변형 개수를 명시해 누락 없이 회수했다.
- 첫 회원 등록/레슨 작성/검색 지우기/설정 열기/사진 선택/일지 복귀/다시 저장 동작이 보임.
- 카메라 권한이 없어도 일지 작성과 기존 사진 선택이 가능하며, 저장 실패 화면에는 입력 내용이 남아 있음.
- 추가 수정 대상: 설정의 연꽃 장식·0~60% 슬라이더·비정상 토글 모양, 첫 시작의 관리자 표기,
  저장 실패의 빨간 재시도 버튼(삭제 동작으로 오해할 수 있어 일반 강조색으로 교체).

### E 모바일 검수 (손실 방지·가져오기)

- 삭제 확인은 대상 레슨 일시와 일지/사진8장 삭제 범위, 취소/삭제를 명확히 표시함.
- 미저장 이탈은 계속 작성/내용 버리기 두 선택으로 구성돼 시트가 겹치지 않음.
- 일부 방향만 촬영한 상태에서도 사진2장 추가가 가능하며, 빠진 방향 촬영을 선택적으로 제공함.
- 갤러리 사진 연결에서 회원·레슨·수업 전후·방향을 지정하고, 촬영 시각 미상은 미상으로 표시함.
- 데이터 안내는 공유 결과에서 민감정보가 항상 제외된다고 오해할 수 있는 문구가 생성돼 수정 대상.
- 일부 촬영 상태는 수업 후 맥락 및 촬영15:52를 명시하도록 수정 대상.

### F 모바일 검수 (입력·비교 예외)

- 키보드가 표시된 상태에서 메모 커서가 키보드 위에 보이고 상단 저장이 접근 가능한 배치 확인.
- 한 기록에 해당 방향 사진이 없으면 합성/다른 방향 대체 없이 해당 없음과 다른 방향/기록 변경을 제공함.
- 공유 실패는 원본 기록과 선택 옵션을 유지하는 화면으로 표현됨.
- 수정 대상: 레슨 일시 선택 달력이 11월14일까지만 표시돼 전체 월 달력으로 교체,
  공유 실패의 근거 없는 원인 설명과 중복 재시도 버튼/빨간 재시도 및 누락된 메모OFF 옵션.

### G 모바일 검수 (나머지 상태)
