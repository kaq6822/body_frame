## 확정한 제품 방향

BodyMark는 필라테스 강사를 시작으로 요가·피트니스 강사까지 확장 가능한 회원 기록 도구다. 한 강사의 휴대폰에서 오프라인으로 사용하며, 주요 탐색은 회원 / 기록 / 설정이다. 로그인·서버·클라우드 동기화·예약·결제·출석·팀 관리는 이번 범위에 포함하지 않는다.

회원의 운동 시작 배경, 목표, 통증·주의사항, 임신·산후 관련 참고 내용은 선택 입력이다. 회원이 전달한 내용과 강사의 관찰을 구분한다. 앱이 진단이나 치료 효과를 단정하지 않는다.

기록 단위는 실제 레슨이다. 레슨 날짜와 시작 시각을 작성·수정 시각 및 사진 촬영 시각과 구분한다. **일지만 / 사진만 / 일지와 사진 모두** 저장할 수 있다. 사진 촬영을 하지 않아도 회원 기록을 이어갈 수 있으며, 사진과 메모를 각각 필수로 강제하지 않는다. 내용이 전혀 없는 기록의 저장 방지는 구현 시 입력 검증에 반영한다.

## 주요 흐름과 검수 결과

| 영역 | 시안에 반영한 동작 |
| --- | --- |
| 회원 관리 | 목록·검색·등록·상세, 운동 배경·목표·주의사항·메모, 기록 없음 |
| 레슨 기록 | 실제 날짜·시각 변경, 선택 메모·사진, 사진만 기록, 키보드 입력, 저장 중·저장 실패·재시도 |
| 촬영 | 손에 든 휴대폰, 정면 → 좌측면 → 우측면 → 후면, 방향별 건너뛰기·재촬영·일부 저장 |
| 촬영 기준 | 같은 회원·같은 방향의 이전 사진, 기준 없이 첫 촬영, 격자·이전 사진 투명도 조절 |
| 기록 열람 | 일지만 있는 상세·사진 있는 상세, 전체 기록·기존 사진 기록 연결, 촬영 시각 별도 표시 |
| 비교 | 같은 회원의 두 기록, 같은 방향 나란히·겹쳐 보기, 사진 부족·방향 없음 |
| 공유 | 선택 방향의 비교 이미지 구성·미리보기·생성 중·생성 실패·재시도 |
| 예외 | 권한 안내·불러오기 실패·검색 결과 없음·삭제 범위 확인·작성 중 나가기 |
| 설정 | 촬영 표시 설정, 정확한 데이터 보관 안내·개인정보 안내 |

사진을 표시하는 모든 이미지 요소에서 잘라 채우는 설정을 제거했다. 특히 마지막 8개 교정 화면은 교정 전후 원본 URL이 동일하고 `contain`으로 표시되는지 대조했다. 원본의 종횡비·방향과 머리·발을 보존하며, 자동 크롭·자세 변형·자동 정렬을 약속하지 않는다.

촬영 화면 3종은 휴대폰 뷰포트 안에 미리보기와 셔터가 들어오도록 보완했다. 나란히 비교와 공유 미리보기는 동일한 두 사진 URL, 동일한 3:4 표시 영역과 `contain` 설정을 사용한다. 공유 이미지의 이름·메모는 기본 OFF, 레슨 날짜·시각은 ON이며 이미지 내부에 브랜드 로고·워터마크를 넣지 않는다.

데이터 안내는 앱이 자체 클라우드 동기화를 제공하지 않는다는 범위로 작성했다. OS의 백업·기기 간 전송까지 금지된다고 표현하지 않는다. 앱 잠금·PIN·생체 인증·앱 내 백업/복원은 추가하지 않았다.

## 다이얼로그에 대한 판단

다이얼로그 자체가 기피되는 것은 아니다. 사용하던 작업을 끊고 결정을 요구하므로 **언제, 얼마나 자주, 어떤 작업에 쓰는지**가 중요하다. 회원 등록·레슨 작성·기록 열람·촬영 같은 반복 작업은 전체 화면으로 구성했다. 날짜·시각 선택은 짧은 선택 시트로, 삭제·작성 취소는 결과 범위를 설명하는 확인창으로 한정했다. 저장 성공 알림창을 매번 띄우거나, 촬영을 강제하는 진입 선택창을 두지 않는다. 저장·공유 진행과 복구 가능한 오류는 화면 안에서 상태와 재시도를 제공한다.

이 판단은 [Apple Modality](https://developer.apple.com/design/human-interface-guidelines/modality), [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets), [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)의 작업 방해 최소화와 상황에 맞는 제시 원칙에 따른 설계 해석이다. 실제 강사 대상 사용성 테스트 결과를 뜻하지는 않는다.

## 검증 범위와 한계

Stitch 원격 리소스 46개의 MOBILE 유형, 실제 PNG 크기와 원격 메타데이터 일치, 원본 크기 스크린샷, 생성 HTML 문구·이미지 표시 방식을 확인했다. 최종 캔버스에 46개가 표시되는지 다시 조회했고 원래 화면 인스턴스 20개를 보존했다. 화면별 리소스 ID와 PNG·HTML 해시는 JSON 목록에 기록했다.

이는 **디자인 시안 검수**다. Flutter 앱 코드·DB·플랫폼 설정은 변경하지 않았다. 생성 HTML은 구현 명세를 보조하는 자료이며 실제 앱 동작을 증명하지 않는다. 실제 기기의 48dp 터치 영역, 글자 확대·스크린리더, 키보드·작은 화면, 카메라 권한·저장·공유, 비동기 취소·중복 저장 방지는 구현 단계에서 검증해야 한다. 기존 개인 앱에서 회원 관리 제품으로 바뀌는 데이터 구조·마이그레이션 역시 아직 구현되지 않았다. 구현·배포 잔여 작업은 ROADMAP.md에서 관리한다.
